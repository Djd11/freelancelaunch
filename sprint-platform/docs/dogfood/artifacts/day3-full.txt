Day 3 – Rebuild the Checkout Welcome Flow in Klaviyo

Objective: Configure a Klaviyo flow that triggers on the Started Checkout metric, adds conditional splits, personalized emails with dynamic content, time delays, and a recovery email, then test it end‑to‑end before publishing.

Imagine a new client hands you a Shopify store that loses 30 % of revenue at checkout. You open Klaviyo, create a new flow, and select the “Started Checkout” metric as the trigger — this fires the moment a shopper clicks “Continue to payment.” Next you drag a Conditional Split block and set the rule “Profile property ‘Number of Orders’ equals 0” so only first‑time buyers enter the welcome branch. Inside that branch you add an Email block titled “Welcome to [Brand]!” and insert {{ person.first_name }} and {{ event.extra.line_items.0.title }} to greet the shopper and show the exact product they just added. After the email you place a Time Delay block set to 1 hour. Then a second Email block “You might love these…”, using {{ event.extra.line_items.0.product_title }} for a personalized recommendation. A second Conditional Split checks the “Placed Order” metric within the last 24 hours; if false, the flow continues to a final Email block “Complete your purchase” with {{ event.extra.checkout_url }} so the shopper can return to their cart. Finally you hit “Preview” → “Send Test Email” to your own inbox, simulate a Started Checkout event via the “Track API” test payload, verify every dynamic tag renders, and only then switch the flow to Live. This click‑by‑click build gives you a ready‑to‑sell checkout recovery automation that clients explicitly request.

Trigger = Klaviyo Metric “Started Checkout”
Conditional Split on profile property “Number of Orders = 0”
Email dynamic syntax: {{ person.first_name }}, {{ event.extra.line_items.0.title }}, {{ event.extra.checkout_url }}
Time Delay block = 1 hour
Second Conditional Split on metric “Placed Order” within 24h
Test using Preview → Send Test Email + Track API test event

Common pitfalls

Using “Placed Order” as the trigger instead of “Started Checkout” – the flow fires too late
Forgetting to escape line_items index (must be .0) causing blank product names
Skipping the 24‑hour Placed Order split, so purchasers still receive abandonment email
Publishing without a test event – live flow sends to real customers with broken links
